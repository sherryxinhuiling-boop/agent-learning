# ReAct 模式：思考、行动、观察

ReAct 是 Reasoning + Acting 的缩写，是目前最主流的 Agent 执行范式。它的核心是把「想」和「做」交替起来。

## 三个步骤

每一轮循环包含三个阶段：

**思考（Thought）** —— 模型用自然语言分析当前情况，说明它打算做什么、为什么。这一步不产生副作用，只是推理过程。

**行动（Action）** —— 模型输出一个结构化的调用请求，指定工具名和参数。这一步由你的代码执行，模型本身不动手。

**观察（Observation）** —— 工具的执行结果被追加回上下文，供模型下一轮参考。

然后进入下一轮思考，如此往复。

## 为什么要显式地「思考」

模型其实可以跳过思考直接给行动。但显式要求它先写出推理过程，有三个实际好处：

第一，准确率更高。让模型把推理写出来，相当于给它更多「计算空间」。

第二，便于排查问题。当 Agent 做错了，你能直接看到它当时在想什么。如果只有行动没有思考，你只能靠猜。

第三，便于人工介入。关键步骤可以让人类先审核这段思考，再决定是否放行。

## 一个典型的执行轨迹

```
Thought: 用户想知道某公司的股价。我需要先搜索，再整理成文件。
Action: search_web({"query": "某公司 股价"})
Observation: [搜索结果...]

Thought: 搜到了。现在把数据写进文件。
Action: write_file({"path": "report.md", "content": "..."})
Observation: 写入成功

Thought: 任务完成，可以回复用户了。
Action: finish({"answer": "..."})
```

## 手写的价值

现在有很多框架把 ReAct 封装好了，一行代码就能跑起来。

但**强烈建议先手写一遍这个循环**。因为 Agent 出问题时，症状通常很模糊 —— 「它答错了」「它卡住了」「它调用了不该调的工具」。只有你清楚循环内部每一步发生了什么，才有能力定位到具体是哪一环出的问题。

面试中如果被问到「你的 Agent 失败了怎么排查」，能说出「我会看它的 Thought 序列，判断是理解偏了、工具选错了、还是观察结果没被正确使用」—— 这句话的价值，远高于「我用了某框架」。
